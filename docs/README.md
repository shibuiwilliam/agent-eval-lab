## Source report

`report/ai_agent_evaluation_report.md` is the report being verified. It is the **input** to this
project, and its formulas and definitions are authoritative — so it is deliberately kept in
Japanese only. Translating it would create a second document competing for that authority. All
references to it elsewhere in the docs are by section number (3.2, 4.11, 8.5, …), which read the
same in either language.

## How the two languages stay in sync

The result pages under `results/` are generated, not written by hand:

- Numbers, figures, verdicts and pass criteria come from `data/results/E*.json` and
  `experiments/registry.yaml`. They are language-neutral, so the two versions cannot disagree
  about a number.
- Only the prose — title, five items, method, verdict reason, findings, figure captions — differs,
  and its English lives in one place, `experiments/registry.en.yaml`.

So when you change a Japanese result page, change it in the experiment script (not the page), and
update the matching entry in `registry.en.yaml`.

```bash
uv run agenteval exp E3-1   # re-run one experiment → writes E3-1.md and E3-1.en.md
uv run agenteval pages      # re-render every page in both languages from existing JSON
uv run agenteval verify     # regenerate summary.md and summary.en.md
```

`uv run agenteval pages` prints `missing_english` for any experiment whose English prose is absent,
so a forgotten translation shows up rather than silently falling back.

The hand-written documents (`plan/`, `IMPROVEMENT`, `results/LIVE*`, `results/README`) have no
such mechanism — they are kept in sync by editing both.
