# E3-10 Prequential evaluation along the change history, and the learning curve

*日本語版: [E3-10.md](E3-10.md)*

## The five items
- Hypothesis: Recording change and test history and feeding in recency and change size makes a sequential deployment work: prediction accrues with history and surpasses the dependency graph alone
- Planted condition: 65 synthetic changes processed in `seq` order; the same unit is changed 2-7 times so lag features take real values. Predicting change t may use only records with seq < t
- Control: Coverage overlap only; the same model with history features removed (ablation); random selection
- Pass criteria: prequential_auc >= 0.75, history_feature_gain > 0.0, late_auc_gt_early_auc == 1, recall_at_budget_30 >= 0.6, beats_coverage_baseline == 1
- Provenance: simulated

## Method
**Change history and test history are recorded as an append-only ledger (`pts/history.py`)**, and recency and change-size features are derived from it. Before this revision changes were an unordered set, so not one lag feature could be written.

The 17 features from the ledger:
- **Recency**: changes since this test last ran / failed / regressed; since this unit was last changed
- **Test history**: run count, historical failure rate, historical regression rate, never-run flag
- **Cross**: regression rate when these units changed; the unit's own regression rate
Plus **change size** (lines added / removed, character delta, units touched, and their logs).

Evaluation is **prequential**: the 65 changes are processed in change-history order, and predicting change t may use **only records with `seq < t`**. The future is structurally invisible, so temporal leakage cannot occur. The first 10 changes are a warm-up; the rest are predicted and scored.

Controls are (a) coverage overlap only, (b) **the same model with history/lag features removed** (ablation), and (c) random selection. The learning curve splits the predicted changes into an early and a late half.

- **The temporal protocol improves selection substantially.** Regression recall at a 30% budget is 0.810, against 0.535 under E3-8's family-level hold-out. Learning also accrues: AUC goes from 0.752 in the early half to 0.769 in the late half. Training on the past to predict the next change — the realistic deployment — works far better than holding out a whole family.
- **Lag features work.** In the ablation, using `lag` alone gives a global AUC of 0.878 — higher than no history features (0.836), all groups (0.747), and coverage alone (0.776). Recency — how many changes since this test last ran or failed, since this unit was last changed — works exactly as industrial PTS treats it.
- **But adding every group makes it worse.** Bringing in the test-side failure rate and the unit cross-history drops it to 0.747. With only 122 positives, 17 correlated features overfit the logistic regression. In this environment regressions are driven by *which unit the change touched*, not by test fragility, so the test-side historical failure rate acts as a confounder: it makes the model suspect the same test even when an unrelated unit changed.
- **Group selection was delegated to inner validation, and it could not decide.** The inner temporal split (train on the first 70% of the prefix, validate on the last 30%) chose `lag` 15 times, `all` 14, `none` 11, `cross` 10, `test_history` 4, `lag+cross` 1, giving AUC 0.761 — short of the 0.878 that fixing `lag` would give. Too few positives fall inside the inner window to tell the groups apart. **Picking `lag` after seeing the results would satisfy both failing criteria, but that is tuning to the criteria, so it was not done.** What is needed is enough history to run inner validation on; several hundred synthetic changes should resolve it.
- **Coverage still dominates within-change ranking.** Within-change AUC is 0.922 for coverage alone against 0.855 for the learned model — the same conclusion as E3-8: the dominant signal in this environment is report 3.2's dependency graph.
- The verdict is FAIL (a flaw in the experiment design). Three of the five criteria are met (prequential_auc, learning accrues, recall). The two misses — `history_feature_gain > 0` and `beats_coverage_baseline == 1` — both trace to **not being able to select the feature group**. With `lag` fixed, AUC is 0.878 and beats coverage (0.776), satisfying both. So **the lag features themselves work as hypothesised; what is missing is the history length needed to choose among groups**.
