# EC-B2P Context-cost attribution prototype: allocation and ledger reconciliation on existing live trajectories

*日本語版: [EC-B2P.md](EC-B2P.md)*

## The five items
- Hypothesis: The components of the cost allocated by position sum to the independent ledger, the position-model premise (total input never decreases) holds on existing live trajectories, and the reconciliation checks react to planted defects.
- Planted condition: Deterministic plants P2, P3 and P4 applied to copies of existing records (only runs where the plant's effect is at least twice the tolerance).
- Control: The ledger (an independent record): the 240 existing live trajectories without plants and the live rows of data/cost_ledger.jsonl.
- Pass criteria: ledger_identity_error <= 0.001, allocation_identity_error <= 1e-09, negative_increment_rate == 0, ledger_match_rate >= 0.95, perturbation_detection_rate == 1.0
- Provenance: live

## Method
Allocate each run's cost to blocks by position from its usage, match ledger rows to trace steps by exact (run_id, step, four token counts) equality (K3), and compare totals. Plant P2 (drop the assistant resend), P3 (price cache writes as input) and P4 (drop one tool result). Nothing is run; existing records are recomputed. See docs/results/EC-B2P.md.

## Findings and limitations
- ledger_identity_error verifies only the unit-price table copy, the ledger-row-to-step matching and that the components sum to the usage total; it does not show that each block was charged correctly.
- A planted-defect detection rate of 1.0 is a plumbing smoke test, not detection sensitivity: eligibility and detection are almost the same quantity.
- allocation_identity_error is a self-check that is near zero by definition and is not evidence for H1; the informative quantities are ledger agreement and the position-model premise.
- The ledger keeps re-run rows for the same run_id (K3); unmatched rows and the naive-matching error are recorded to show why exact matching is used.
- Plant P4 uses the smallest eligible j per run; the chosen j counts are recorded.
