# E3-2 Selection by semantic impact estimation

## The five items
- Hypothesis: Impact tags enumerated from a prompt diff select the date-related tasks and capture the flipped tests with high recall
- Planted condition: v02_dateformat (a change to the date-format instruction)
- Control: v02b_tone, a diff that changes only tone (no runs needed — the diff alone is used)
- Pass criteria: recall_of_flipped >= 0.8, control_selected_ratio <= 0.2, precision_gain_vs_coverage > 0.0
- Provenance: simulated

## Method
We enumerated impact tags from the v01 → v02_dateformat prompt diff (section: date_format),
vectorised each task's tags, category and kind with TF-IDF over character 2–3-grams, and
selected the tasks whose cosine similarity was at least the 0.15 threshold (report 3.3).
Flips follow the ADR-009 definition (disagreement rate over matched repeats > the flake band).
The control is v01 → v02b_tone (tone-only diff, no runs created), where we look at
selected_ratio under the same procedure. We compared precision against coverage alone (the
tasks that reference the date_format section).
Because live was unavailable, tag enumeration uses deterministic extraction from the diff text
(`impact.tags_offline`) rather than an LLM, so provenance is simulated. The live path that
has Haiku enumerate the tags (`impact.tags_live`) is implemented but not executed.
