## 5項目
- 仮説: (H1) 「可視テストが緑になった最初の試行を採用し、最大 k 回」の方策の成功率と静かな誤りの率は、タスクごとの類確率 (s, w, f) の閉形式で表せる。(H2) W の多い版ほど pass@k と実現可能な成功率の差 $G_k$ が大きい。(H3) 再試行は静かな誤りを増やす（$P_k(\text{W})$ が k とともに増える量が 0 より大きい）

- 対照: (a) 観測上 w = 0 のタスクと合成の格子での恒等式 $P_k(\text{成功}) = \text{pass@}k$（実装の自己検査）、(b) `c12_null` と c01 の $G_3$ の差（記録のみ）

## 方法

### 量の定義（NEW_IDEA EC-R2 の理論）
- タスク t の 1 試行の類確率 $(s_t, w_t, f_t)$。S / W / F の分類は EC-R1 と同じ。分類が実機で正しく働く前提（正解パッチの台本 48/48 が可視・隠しとも合格、特殊化パッチの台本 42/42 が可視合格・隠し不合格。W2-V2、2026-11-07、simulated）は EC-R1.md の方法「真値の前提条件の確認」に記録した。結果ではない
- 閉形式: $P_k(\text{成功}) = s\frac{1-f^k}{1-f}$、$P_k(\text{W}) = w\frac{1-f^k}{1-f}$（f = 1 のときは 0）、$\text{pass@}k = 1 - (1-s)^k$、$G_k = \text{pass@}k - P_k(\text{成功})$
- 経験値（ノンパラメトリック）: タスクの試行列から k 個を**順序付きで非復元に**選ぶすべての選び方について方策を実行した平均（U 統計量。k ≤ 試行数のとき不偏）。pass@k は Chen らの不偏推定量 $1 - \binom{n-c}{k}/\binom{n}{k}$
- 版の値はタスク間の等重み平均。区間はタスク単位のクラスタ・ブートストラップ（B = 2,000、パーセンタイル法。c01 と c13 は同じタスクで対にする）
- 入力は段 `corpus` の live の run だけ（EC-R1 と共用）。試行の順序は反復番号 r0〜r5 の順

### 指標の定義
| 指標 | 定義 | 種類 |
|---|---|---|
| `closed_form_mae_k1to4` | 各タスクの 6 試行を反復番号で前半 3・後半 3 に分け、前半の頻度から閉形式で $P_k(\text{成功})$ を予測、後半から経験値を出す（k ≤ 3 は非復元の全順序の列挙、k = 4 は後半 3 試行からの復元抽出 1,000 回）。版ごとにタスク平均した予測と経験値の差の絶対値を k = 1..4 で平均し、c01 と c13 でさらに平均 | 原典の主張そのもの。ただし情報は少ない（下記） |
| `g3_diff_ci_low` | 経験値の $G_3(c13) - G_3(c01)$（6 試行すべてを使う U 統計量）の 95% 区間の下限 | 情報あり |
| `silent_wrong_monotone_c13` | c13 の $P_k(\text{W})$ が k = 1..4 で非減少なら 1（閉形式と経験値の両方で） | **自己検査**（下記） |
| `silent_wrong_gain_c13_ci_low` | c13 の経験値 $P_4(\text{W}) - P_1(\text{W})$ の 95% 区間の下限 | 情報あり（H3 の量的な主張） |
| `identity_error_w0` | 観測上 w = 0 のタスク（6 試行に W が無い）と合成の格子（s ∈ {0, 0.05, …, 1}、w = 0）で、k = 1..4 の $\lvert P_k(\text{成功}) - \text{pass@}k\rvert$ の最大値（閉形式どうし、経験値どうしの両方） | **自己検査** |

- **`silent_wrong_monotone_c13` は定義上ほぼ必ず 1 になる**。閉形式 $w(1-f^k)/(1-f)$ は k について非減少であり、経験値も、同じ試行の並びで k を 1 増やすと結果が F から S か W に変わることしかないので非減少になる。0 になるのは実装の誤りのときだけなので、FAIL の検出として残し、H3 の証拠にはしない。H3 の量的な主張は追加の `silent_wrong_gain_c13_ci_low > 0`（再試行で増える W の量が区間で 0 より大きい）で検査する
- `identity_error_w0` も代数的な恒等式で、浮動小数点の誤差以外では 0 になる。合成の格子を常に含めるので、観測上 w = 0 のタスクが無くても空虚にはならない（観測上のタスク数 `identity_cases_w0` を記録する）
- 記録のみ: 版ごとの pass@k・$P_k(\text{成功})$・$P_k(\text{W})$・期待試行数の表（k = 1..6）、c12 − c01 の $G_3$ の差と区間、Θ 上の最適な k の分布（4.0 節の NV(k)。THETA.md の Θ）、「再試行が 1 回目から ROI を下げる」w/s の閾値の分布、反復の独立性の診断（下記）

### 閉形式と経験値の比較について（基準 0.05 の到達可能性）
**推定誤差だけで生じる MAE の期待値を計算した**。閉形式が正しい（試行がタスク内で独立同分布）と仮定し、前半 3・後半 3 の分割による推定誤差だけで MAE がどれだけ出るかを模擬した（simulated。仮定: タスクごとの類確率を平均 (s, w, f)、集中度 κ の Dirichlet で 24 タスク分引く。各 400 回）。

| (0.60, 0.08, 0.32)（c01 相当） | 2 | 0.053 | 0.54 | 0.128 |

- **SPEC どおりの実装での値（W0-Z、W1-I7 のレビュー）**: 上の表は W0-D3 の模擬（k = 4 だけ復元抽出の変種で計算）の値である。SPEC.md 9.4 節どおりの実装（k ≤ 3 は非復元の全順序の列挙、k = 4 は後半 3 試行からの復元抽出）で同じ仮定を模擬すると、**E[MAE] は 0.061〜0.077（simulated）**になる。床が閾値 0.05 を上回る側に寄るので、「基準 0.05 は硬貨投げか、それより悪い」という結論は強まる。
  **W3-A2 の帰無分布の再模擬は、模擬用に書き直した関数ではなく、実装の関数（`econ/retry.py`）そのもので行う**（模擬と実装の細部の違いで帰無分布がずれるのを避ける）

- **結論: 基準 0.05 は、閉形式が完全に正しくても約半分の確率でしか満たされない**。推定誤差の床（期待値 0.05〜0.07）が閾値とほぼ同じ大きさで、基準は硬貨投げになる（REPORT §11 の E3-9 と同じ型）
- さらに、この比較の**情報そのものが少ない**。閉形式は「タスク内で試行が交換可能」という仮定の下の代数であり、経験値は同じ試行プールからの再標本化である。前半・後半の分割は推定誤差を足すだけで、分割を全通り平均する（leave-one-out や全分割の平均）と推定誤差は消えるが、比較は「プラグイン推定量と U 統計量の偏りの差」になり、やはり閉形式の正しさを検査しない。仮定が破れる典型（カセットの衝突で反復が同一になる K5）では、前半も後半も同じように潰れるので分割の比較では検出できない
- **代替の提案（基準は暫定のまま。W3-A2 で決める）**
  1. `closed_form_mae_k1to4` の閾値を、パイロットの c01 の類確率の分布から上と同じ模擬で求めた**帰無分布の 95% 点**に置き換える（上の仮定では 0.13〜0.17）。位置づけは「実装と前半・後半の交換可能性の検査」で、主張の主軸にはしない
  2. 反復の独立性を直接見る診断を記録する: 同じタスク・同じ版の反復で軌跡（ツール呼び出し列と最終差分のハッシュ）が完全に一致する割合 `identical_trial_rate`（塩が効いていれば 0 に近い）、反復番号の前半と後半の類頻度の差（時間的な漂流）
  3. EC-R2 の主張の重みを、閉形式との一致ではなく `g3_diff_ci_low > 0` と `silent_wrong_gain_c13_ci_low > 0`（実現可能な pass@k の上方バイアスの大きさと、再試行による W の増加量）に置く

  **この基準の不合格を NEGATIVE と書くのは、c13 の f̂ が 0.15 以上のときに限る**（f̂ < 0.15 なら「到達上限による検出力不足」と書く）。この読み方は c13 のデータを見る前に、ここで固定する。基準の値は変えない

- 難度を調整しない（ADR-043）ので、c01 の F が少なく再試行の場面はほぼ c13 の F からだけ生じる。これは「気づき・限界」に書く
- **判定での扱い（ADR-045 案、2026-11-07、データを見る前。G2 でユーザーが選ぶ）**: 上の「$\hat f$ < 0.15 なら検出力不足」は、`agenteval verify` が基準ごとの「適用しない」を表せないため、そのままでは EC-R2 全体が FAIL になる。
  案は、`silent_wrong_gain_c13_ci_low > 0` に適用条件 `c13_f_hat >= 0.15` を付けることである（`c13_f_hat` = 段 `corpus` の c13 の bugfix の試行の F の頻度のタスク等重み平均、来歴 live）。条件が偽ならその基準は「N/A（到達上限による検出力不足）」として判定から外す。N/A は合格ではなく、結果ページと `summary.md` に明記する。閾値 0.15 と基準の値は変えない。verify と実験スクリプトの対応（implementer）が済むまで registry には足さない

### FAIL と NEGATIVE の区別（判定時の指針）
