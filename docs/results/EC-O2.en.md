## The five items
- Hypothesis: Four deterministic checks detect every run in which the corresponding harness defect was planted, and raise no alarm on runs from a defect-free harness.

The 19 EC-S1 tool-route injection runs and the specialization-patch runs are recorded only.

- Provenance: simulated

## Method
Create the 20 planted runs (scripted agent, Docker, no API cost; the plants come from obs/plants.py and their parts are rebuilt for every run) and apply the four checks of obs/integrity.py. Read the control runs from the store (the gold-patch runs and the 19 EC-S1 tool-route twin runs, r0 only; probes are not controls). Detection counts only when the matching check fires. Checks use independently observed records (snapshot diffs, audit-hook logs, permission decisions), not tool self-reports. See docs/results/EC-O2.md.

## Findings and limitations
- The checks judge from independently observed records, not tool self-reports; a planted defect never declares itself, so a check that reads only a flag cannot detect it.
- Observation range: the effects area (the audit hook's own log) is outside observation, so writes to it never reach the four checks. The plants do not use it, so criteria are unaffected, but zero alarms never means no effects-area activity. Unobservable (hook_missing) counts in controls are reported.
- Off-diagonal cells of the 4x4 confusion matrix are not criteria; one plant reacting in several checks is not an error.
- Control runs and their alarms are summarised (by check and group). Additional controls (the 19 EC-S1 tool-route injection runs, specialization patches) are recorded only.
- Applying the checks to the live corpus (live_corpus_alarms) is recorded only: live runs have no ground truth, so each alarm has to be investigated by hand.
