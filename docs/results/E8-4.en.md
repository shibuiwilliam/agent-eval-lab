# E8-4 Dual-track κ

*日本語版: [E8-4.md](E8-4.md)*

## The five items
- Hypothesis: The mock-vs-live outcome agreement κ falls when drift is injected
- Planted condition: After bump_external(v2), re-run the tasks that use external_lookup
- Control: κ before injection
- Pass criteria: kappa_before >= 0.6, kappa_drop >= 0.3
- Provenance: simulated

## Method
Restricting to tasks that always use `external_lookup` (the mixed category), we ran the same
task set on a "mock track" (external service v1) and a "live track" (the current external
service) and measured agreement on `outcome.passed` with Cohen's κ (report 8.6).
Before injection both tracks use v1; after injection only the live track has
`DriftInjector.bump_external(v2)` applied.
κ comes from `sklearn.metrics.cohen_kappa_score`. When either group's outcomes have no
variance, κ is undefined, so we treat perfect agreement as 1.0 and perfect disagreement as 0.0
(an implementation note).

## Findings and limitations
- Target tasks (those using external_lookup): ['T-004', 'T-028', 'T-029', 'T-030', 'T-404']
- **A pre-injection κ of 1.0 is trivial given sim's structure.** In sim mode a given (task, seed, repeat) executes deterministically, so if the external service version is the same the mock and live tracks must agree. Under live, responses vary even under identical conditions and κ would be below 1.0. This experiment therefore shows only that "κ falls when drift is injected"; it does not amount to verifying that "κ is high before injection".
- The mechanism behind the drop in κ is that the external service's response key changes from `price` to `unit_price`, so the agent cannot read the price and fails. The mock side is still on v1 and passes.
