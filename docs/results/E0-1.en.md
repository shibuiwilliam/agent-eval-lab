# E0-1 Agreement between the simulated agent and live (sim validity)

*日本語版: [E0-1.md](E0-1.md)*

## The five items
- Hypothesis: Trajectories built with sim (ADR-008) agree with live trajectories on the same (task, version, repeat) at the level of the quantities evaluation methods look at
- Planted condition: Run the same 10 tasks × 3 versions × 3 repeats under both live and sim and match up the quantities the evaluation methods use
- Control: Compare matched (task, version, repeat) triples; never compare across versions
- Pass criteria: outcome_agreement >= 0.7, pass_rate_gap <= 0.15, tool_sequence_similarity >= 0.6, version_ordering_preserved == 1, n_separable_version_pairs >= 1, ordering_ok_on_separable_pairs == 1
- Provenance: live

## Method
We executed the same (task, version, repeat) triples under both live and sim and matched up the
quantities the evaluation methods take as input. Live uses `AGENTEVAL_LLM_MODE=record`
(Haiku 4.5, prompt caching enabled); sim uses the same triples from the existing corpus.
Matching is an exact match on (task, version, repeat); no comparison is made across versions.
Quantities compared:
  - agreement rate of `outcome.passed` (how often the same triple agrees on pass/fail)
  - per-version pass-rate difference (how far sim shifts the level away from live)
  - tool-name sequence similarity (the complement of normalised edit distance, the same
    definition as in `pts/selector.py`)
  - whether version ordering is preserved (do live and sim agree on the ordering of pass rates)
This is the one experiment whose provenance is `live` (being a **comparison** of live and sim,
both sets of numbers appear. They are split into separate columns in the table, and no mixed
statistic is constructed).
