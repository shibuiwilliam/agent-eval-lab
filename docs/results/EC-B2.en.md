## Findings and limitations
- ledger_identity_error verifies only the price-table copy, the row-to-step matching and the component sum, not block-wise attribution; control (a) is the only check of attribution by lifetime. The number of runs checked for the identity is recorded; with a ledger match rate below 0.95, or zero checked runs, the value is withheld and the experiment fails.
- Control (a) is simulated (synthetic usage, 1 token = 4 bytes) and almost determined by arithmetic; it rules out implementations that attribute by output size alone. Absolute amounts must not be compared with live values.
- H2: the c04 verbose output may change behaviour (step count), so the extra cost D_t includes non-resend increments; the ratio can exceed 1 or fall below 0.8.
- H3's primary metric is the within-run counterfactual |e_off - e_on|; most information is in e_on. A broken cache chain (history cache not read in 'on' runs, or cache beyond the prefix in 'off' runs) counts as an implementation error.
- The c04 and c01 tool definitions and prompts were checked to be identical so the prefix P can be shared; per-version e_on is recorded for c04 only (c12 and c13 have a different system prompt).
