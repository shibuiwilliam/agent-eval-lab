## The five items
- Hypothesis: Every test that actually flipped under a tool change is contained in the candidate set T_cand(Δ), and the candidate set is meaningfully smaller than the full suite
- Planted condition: v06_toolschema_v2 (argument change in calendar_search). Flips are measured from v01 → v06
- Control: A synthetic change Change(kind=tool, components={mail_send}). Tests that never call mail_send must not enter the candidate set
- Pass criteria: recall_of_flipped >= 1.0, candidate_ratio <= 0.6, control_false_candidates == 0
- Provenance: simulated

## Method
From every run of v01_baseline we extracted `U(t)` (the tools called, the prompt sections
referenced, the resources touched) and took the tasks intersecting the elements that the
`Change` touches, `C(Δ)`, as the candidate set `T_cand(Δ)` (report 3.2).
The planted condition is v01 → v06_toolschema_v2 (a rename of `calendar_search`'s arguments,
`kind=tool`). A flip is a task whose pass rate crossed 0.5 between v01 and v06; tasks whose
outcomes vary across v01's repeats (the flake band) are not counted as flips. The control is
the synthetic change `Change(kind=tool, components={mail_send})`, where we checked that the
selected tasks really do call `mail_send` in another version's trajectories (v03) — matching
the selection criterion against the observed behaviour.
