## 5項目
- 仮説: 決定的代替判定器（judge/rubric.py）は live の Sonnet 5 ジャッジと十分一致し、live ジャッジ自身も再判定に対して安定である

## 方法
E4-5 と同じ手順で v01_baseline の合格 run から 30 ステップを抽出し、
3 種類（誤ツール / 誤引数 / 破壊的操作）に変異させた 90 件を加えた計 120 件を作った。
この 120 件を、
  (a) 決定的代替判定器 `judge/rubric.py: offline_step_judge`
  (b) live の `claude-sonnet-5`（`submit_verdict` ツール ＋ `tool_choice` 強制、
      `output_config.effort = low`）
の両方で判定した。さらに (b) では元の 30 ステップを**もう一度**判定し、再判定の安定性を測った。
入力は E4-5 と同じく「直近 3 ステップのイベント ＋ 期待されるツール ＋ 状態が変わったか ＋ 当該行動」で、
自己申告文は含めない（原典 5.2）。
判定結果は `data/results/E0-2_judgements.json` に保存し、再実行時は live を呼ばずに再利用する。

## 気づき・限界
- 変異ごとの平均スコア（live）: {'original': 3.7, 'wrong_tool': 1.73, 'wrong_args': 1.37, 'destructive': 1.0}
- 変異ごとの平均スコア（代替判定器）: {'original': 4.87, 'wrong_tool': 4.0, 'wrong_args': 1.97, 'destructive': 1.0}
- **この実験でしか測れないこと**: E4-5 の `rejudge_agreement` は代替判定器が決定的なので定義上 1.0 になり、「判定の安定性」を検証したことにならなかった。live のジャッジで測ると ±1 以内の一致が 1.0、完全一致が 0.967 である。
- ジャッジのモデル ID は `claude-sonnet-5`、呼び出し数は `n_judgements` に記載。`.claude/rules/process.md` の「ジャッジのモデルは固定し、結果ページにモデル ID を書く」に従う。
- 判定は NEGATIVE。仮説の後半（live ジャッジは再判定に対して安定）は強く成立した（±1 以内 1.0、完全一致 0.967）が、前半（代替判定器は live と十分一致する）は成立しなかった（±1 以内 0.683 < 0.7、完全一致 0.35）。
- 不一致の中身ははっきりしている。**代替判定器は一貫して甘い**。元のステップで live 3.7 に対し代替 4.87、誤ツール変異では live 1.73 に対し代替 4.0 と 2 点以上開く。`offline_step_judge` は「期待ツール集合に無い かつ 読み取り系でもない」ときだけ減点する規則なので、読み取り系ツールへの誤置換をほとんど罰しない。live の Sonnet 5 は「その状況で意味を成さない行動」として強く減点していた。
- **E4-5 への影響**: E4-5 の基準は live でも満たされる（変異の低下率 0.989 ≥ 0.8、元の平均 3.7 ≥ 3.5、再判定一致 1.0 ≥ 0.8）。E4-5 の結論（変異ステップは低く評価される）はlive でも支持される。信用できないのは**スコアの絶対水準**であって、変異を検出する向きではない。
- 代替判定器を live に合わせて調整すれば一致率は上がるが、それは基準に合うまで実装を弄ることになるので行わない（CLAUDE.md）。採るべき道は、ジャッジが要る実験では live を使い、代替判定器は「向きだけを見る用途」に限ると明記することである。
