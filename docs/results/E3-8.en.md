# E3-8 Test selection from a learned failure model

*日本語版: [E3-8.md](E3-8.md)*

## The five items
- Hypothesis: Learning the regression probability from change x test features catches regressions at a higher recall than random selection at the same budget
- Planted condition: 37 synthetic changes built per report 3.8's cold start (prompt / config / tool / model / fault / two-factor)
- Control: Random selection, baseline failure rate only, coverage overlap only, uncertainty H(p-hat)
- Pass criteria: roc_auc >= 0.75, recall_at_budget_30 >= 0.8, recall_ratio_vs_random >= 2.0, escape_ratio_vs_random <= 0.5, control_random_recall <= 0.6
- Provenance: simulated

## Method
Following report 3.8's "cold start", **37 synthetic changes** were built by perturbing v01_baseline (13 prompt-section additions/removals / 7 config / 1 tool schema / 1 model swap / 12 tool faults / 3 two-factor). Each change x 46 tasks x 5 repeats ran in sim into `data/pts_corpus/`, kept separate from the existing corpus.

Each training row is a (change, test) pair, labelled **regressed** (the baseline passed at a repeat and the target failed at the same repeat). Features are report 3.4's table (recent pass rate, flip count, score margin, coverage overlap, flake rate) plus the cross features industrial PTS uses (how the change's units and the test's units overlap, the change kind, the task kind), plus **within-change percentile ranks** (ADR-027).

**Discipline against leakage**: features come only from the baseline history and the change metadata; the target version's runs are used for labels only. Features derived from other changes' labels are computed inside the training fold. Cross-validation is **leave-one-group-out over change families**, and the model is chosen by an **inner** cross-validation on the training folds only (never by looking at the held-out score).

Selection is greedy by predicted risk `p_fail / cost` up to the budget.
