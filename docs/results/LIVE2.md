# live 検証レポート 第 2 次（R1〜R5 の実施）

実施日: 2026-09-13（同日 2 回目）/ 被験 `claude-haiku-4-5-20251001` / ジャッジ `claude-sonnet-5`
`IMPROVEMENT.md` の R1〜R5 を実施した記録。第 1 次は [LIVE.md](LIVE.md)。

## 1. 結論を先に

第 1 次の live 検証では「エージェント側」の欠陥が見つかった。
第 2 次では、**評価器側とコーパス側の欠陥**が 3 件見つかった。いずれも sim だけでは検出できない。

| # | 見つかったこと | 影響 |
|---|---|---|
| L6 | 植込み版 **v02_dateformat の欠陥が実モデルでは再現していなかった** | v02 の「反転テスト」は sim の産物。E3-2 / E3-4 / E8-5 がそれに依存していた |
| L7 | モデル指紋の合成統計量が、識別力の無い項で信号を薄めていた | live ではモデル入替を p = 0.118 で検知できず（人工分布では p = 0.002 だった） |
| — | 代替判定器は live ジャッジと**一致しない**（±1 以内 0.683、完全一致 0.35） | ジャッジを使う実験のスコアの絶対水準は sim では語れない |

加えて、第 1 次で立てた診断のうち **1 件を live で否定して取り下げた**（R4 / ADR-014）。

## 2. R1: ジャッジを live にする → 実験 [E0-2](E0-2.md)

E4-5 と同じ 30 ステップ ＋ 3 種の変異（計 120 件）を、live の Sonnet 5 と決定的代替判定器の両方で判定した。

| 指標 | 基準 | 結果 |
|---|---|---|
| 代替判定器と live の一致（±1 以内） | ≥ 0.7 | **0.683** ✗ |
| 変異ステップの低下率（live ジャッジ） | ≥ 0.8 | 0.989 ○ |
| **再判定の一致（live ジャッジ）** | ≥ 0.8 | **1.000**（完全一致 0.967）○ |
| 元のステップの平均スコア（live） | ≥ 3.5 | 3.70 ○ |

判定 **NEGATIVE**。仮説の後半（live ジャッジは安定）は強く成立したが、前半（代替判定器は一致する）は成立しなかった。

不一致の中身は一方向である。**代替判定器は一貫して甘い**。

| | 元のステップ | 誤ツール | 誤引数 | 破壊的操作 |
|---|---|---|---|---|
| live Sonnet 5 | 3.70 | **1.73** | 1.37 | 1.00 |
| 代替判定器 | 4.87 | **4.00** | 1.97 | 1.00 |

`offline_step_judge` は「期待ツール集合に無い かつ 読み取り系でもない」ときだけ減点するので、
読み取り系ツールへの誤置換をほとんど罰しない。live の Sonnet 5 は「その状況で意味を成さない行動」として強く減点していた。

**E4-5 への影響**: E4-5 の 4 基準はすべて live でも満たされる。E4-5 の結論（変異ステップは低く評価される）は
live でも支持される。信用できないのは**スコアの絶対水準**であって、変異を検出する向きではない。

**これは sim では原理的に測れなかった項目である**。E4-5 の `rejudge_agreement = 1.0` は
代替判定器が決定的だから 1.0 になっていただけで、「判定の安定性」を検証したことになっていなかった。
live で測ると ±1 以内 1.000 / 完全一致 0.967 で、実際に安定していた。

## 3. R2: モデル指紋を live で取る → [E8-6](E8-6.md)

プローブ 30 問 ＋ ミニタスク 10 問を、Haiku 4.5 で 2 回、Sonnet 5 で 1 回取得した（120 呼び出し）。

| 統計量 | 対照（同一モデル 2 回） | 入替（Haiku → Sonnet） |
|---|---|---|
| 合成（応答長 ＋ 先頭一致率 ＋ ツール選択）＝改訂前 | p = 1.000 | **p = 0.118**（検知できず） |
| 応答長だけ（ADR-013）＝改訂後 | p = 0.716 | **p = 0.046**（検知） |

人工分布では合成統計量でも p = 0.002 で検知できていた。**人工分布に助けられていた結果だった**。

原因は、合成統計量の 2 項が帰無仮説と対立仮説で同じ値を取ること。
- 先頭 20 文字の一致率: 同一モデル 2 回でも 0.2、別モデルでも 0.1
- ミニタスクのツール選択: 10 問中 **8 問が `__no_tool__`**（実モデルはツールを呼ばず文章で答える。第 1 次の L1 と同じ現象）

ADR-013 で応答長だけの順列検定を追加し、live の判定に使う。
**合格基準は緩めていない**: 人工分布に対する 2 基準はそのまま残し、live に対する 2 基準を追加した（判定は厳しくなる）。
入替の p = 0.046 はプローブ 30 問では 0.05 ぎりぎりで、安定には増量が要る。

## 4. R3: E0-1 の基準は書き直さなかった

`version_ordering_preserved` が未達なのは「同点に近い量の順序を基準にしたから」だと考えていた。
反復を 3 → 6（各版 n=60）に増やして測り直すと、**信頼区間が重ならない版の組は 0 組**だった
（95% 区間の半幅 ±0.063）。v01 / v03 / v07 は live でも sim でも合格率が同じで、
**順序を検証できる版の組がそもそも無かった**。

基準を書き換えるのではなく、順序を検証できる版（v02_dateformat）を比較対象に加えた。
診断指標 `n_separable_version_pairs` と `ordering_ok_on_separable_pairs` を追加した。

## 5. R4: live で前提が否定されたので取り下げた（ADR-014）

E3-3 / E3-7 の FAIL を「冗長性ペナルティの類似度がツール名列だけなので同種タスクが相互に重複と判定される」
と診断し、正規化引数を含める改訂を計画していた。live の軌跡で測り直すと前提が成り立たなかった。

| | 異なるタスク間の類似度（平均） | 0.8 超の組 | 相異なるツール名列 |
|---|---|---|---|
| live（10 タスク） | 0.257 | 1/45 = **2%** | 9 種 |
| sim（同じ 10 タスク） | 0.431 | 3/45 = 7% | — |
| sim（全 46 タスク） | 0.455 | 115/1035 = **11%** | **13 種**（最大クラスタは 10 タスクが同一列） |

実エージェントの軌跡はタスクごとに十分ばらけており、冗長性ペナルティは意図どおり
「本当に似ているテスト」だけを落とす。潰れていたのは**シミュレート・エージェントの軌跡の多様性**の側だった。
類似度の定義は変更せず、E3-3 / E3-7 の診断文を訂正した。

## 6. L6: 植込みが植え込まれていなかった

E0-1 に v02_dateformat を加えて live 実行したところ、合格率 0.90（v01 は 0.933）で、sim の 0.617 と食い違った。

| | `calendar_create` の `start` 引数 | 利用者への文章 |
|---|---|---|
| live（12 件） | `2026-09-21T15:00`（**ISO のまま**） | 「来週月曜（2026/09/21）…」 |
| sim（100 件） | `2026/09/21T15:00` | スラッシュ |

**実モデルはシステムプロンプトとツール定義が食い違ったときツール定義を優先する**。
「YYYY/MM/DD を使え」という指示は利用者向けの文章にだけ適用されていた。

v02 のプロンプトに「この取り決めはツールの説明文より優先される。`calendar_create` の start / end も
スラッシュ区切りで渡すこと」を明記して植込みを立て直した。
live で 20 run 検証したところ `calendar_create` の引数は **8/8 件がスラッシュ書式**になり、
合格率は 0.90 → **0.60** に下がった。植込みが実モデルでも効くようになった。

これは基準の変更ではなく、**植込みが植え込まれていなかったのを直した**ものである。
