# E4-4 Partial credit from partial-order milestones

*日本語版: [E4-4.md](E4-4.md)*

## The five items
- Hypothesis: Partial credit is consistent with the quality ordering of versions and awards full marks to legitimate paths that differ only in order
- Planted condition: The v01 / v03 / v05 corpora, plus synthetic trajectories with different orderings
- Control: A synthetic trajectory whose arrival order violates the constraints is penalised
- Pass criteria: spearman_rho >= 0.6, synthetic_ok == 1
- Provenance: simulated

## Method
For each run in the corpus we averaged the `milestone_score` recorded at execution time (a
partial-order judgement over the per-step state sequence) by version, and took the Spearman
rank correlation against the acceptance pass rate of the same version (report 4.5).
For the synthetic trajectories we hand-built three: (a) the constrained order (search → create
→ check), (b) a wrong order (check → create), and (c) a trajectory that never arrives, and
confirmed that the partial credit came out as expected.
A milestone reached in violation of an `after` constraint is not counted toward partial credit.

## Findings and limitations
- Per-version values: [{'version': 'v01_baseline', 'milestone_score': 0.9384, 'pass_rate': 0.7935}, {'version': 'v03_noverify', 'milestone_score': 0.7399, 'pass_rate': 0.7935}, {'version': 'v05_unsafe_delete', 'milestone_score': 0.8949, 'pass_rate': 0.75}, {'version': 'v07_step_minimizer', 'milestone_score': 0.7399, 'pass_rate': 0.7935}]
- Spearman is taken over 4 versions, so its statistical strength is weak (the p value is reported alongside). Adding versions would stabilise it, but that only increases the input to the rank correlation — it does not change the substance of what is being verified.
- Synthetic-trajectory verdicts: correct order = 1.0, wrong order = 0.667, never reached = 0.333. In the wrong order, M3 (after=[M2]) earns no partial credit.
- Diagnostic (outside the criteria): taking the same correlation over all 12 versions of the corpus gives ρ = 0.63 (p = 0.028). Across the 4 versions the catalogue specifies, the simulator fix based on live verification (IMPROVEMENT.md L5) left v01 / v03 / v07 with nearly identical pass rates, making the rank correlation hard to define.
- The verdict is FAIL (a flaw in the experiment design). The ordering judgement on the synthetic trajectories came out as expected and the partial-order implementation itself works. What did not hold is "partial credit is consistent with the quality ordering of versions", because only 4 versions are compared and 3 of them have nearly tied pass rates (p = 0.728, not significant). Proposed fix: add versions, or take the correlation per task rather than per version (either changes the criteria, so an ADR would be needed).
