## The five items
- Hypothesis: When the external service changes, F drops and the mismatching keys are identified. Expired cassettes are flagged
- Planted condition: DriftInjector.bump_external(v2) (price → unit_price, plus value changes)
- Control: Before the change, F = 1.0
- Pass criteria: fidelity_after <= 0.5, fidelity_before == 1.0, mismatch_keys_match == 1, ttl_detection_rate == 1.0
- Provenance: simulated

## Method
We recorded the responses of external service v1 into cassettes
(`data/cassettes/external/`), then compared them against a service changed as by
`DriftInjector.bump_external(v2)` (renaming `price` → `unit_price` plus value changes) to
obtain the fidelity `F` (report 8.5).
Matching applies layered assertions in order (exact match → structural match → semantic
judgement) and counts which layer made the call.
For TTL, a cassette past `ttl_days` from its recording date counts as expired; we deliberately
created expired cassettes and measured the detection rate. This experiment uses no LLM.

## Findings and limitations
- Mismatching keys: ['price', 'unit_price'] (changed keys: ['price', 'unit_price'])
- Judgements per layer (after the change): {'exact': 0, 'structural': 0, 'semantic': 5}
- Because the change renames a key, layered assertions never even reach "structural match" and fall through to the "semantic judgement" layer. A change only to values would be caught at the structural layer.
- Since we define the external service ourselves, this is not a verification that "a real service changed". What was verified is that the computation of F, the identification of mismatching keys, and the TTL judgement all work.
