## The five items
- Hypothesis: Recall R(n) falls as noise n rises, and the summarising strategy (v08) has a higher AUC than raw (v01)
- Planted condition: 4 niah task types × n ∈ {0, 2, 4, 8} × 3 repeats
- Control: At n = 0 both versions have high recall
- Pass criteria: recall_n0 >= 0.8, recall_drop_v01 >= 0.2, auc_gain_v08 >= 0.1
- Provenance: simulated

## Method
For the 4 tasks of `kind: niah`, `NoiseInjector` appended irrelevant long text (1,200
characters per step) to the tool responses of n steps from step 0 onwards, and we ran
n ∈ {0, 2, 4, 8} × 3 repeats (report 4.9). Recall R(n) is the fraction of runs whose final text
contains the `key_fact`.
The versions are v01_baseline (raw) and v08_summarize_ctx (tool results older than k steps are
replaced by a summary). AUC uses the trapezoid rule with n normalised to 0–1.
Because this experiment injects noise, it does not use the corpus runs — it generates runs
inside the experiment (the injection is recorded in the manifest).

## Findings and limitations
- Raw recall data: [{'version': 'v01_baseline', 'n': 0, 'recall': 1.0, 'runs': 12}, {'version': 'v01_baseline', 'n': 2, 'recall': 0.3333, 'runs': 12}, {'version': 'v01_baseline', 'n': 4, 'recall': 0.3333, 'runs': 12}, {'version': 'v01_baseline', 'n': 8, 'recall': 0.3333, 'runs': 12}, {'version': 'v08_summarize_ctx', 'n': 0, 'recall': 1.0, 'runs': 12}, {'version': 'v08_summarize_ctx', 'n': 2, 'recall': 0.3333, 'runs': 12}, {'version': 'v08_summarize_ctx', 'n': 4, 'recall': 0.3333, 'runs': 12}, {'version': 'v08_summarize_ctx', 'n': 8, 'recall': 0.3333, 'runs': 12}]
- The simulator's recall model is a deterministic rule that lowers recall probability linearly in the fraction of characters occupied by noise in the conversation sent. The summarising strategy (v08) truncates old tool results to the first 160 characters, dropping the noise appended at the end and keeping the key_fact (which sits near the front of the body). So any advantage to v08 is a structural consequence of where the injection happens and how the summary is implemented — it is not evidence that summarising generally helps recall.
- Report 4.11 notes that summarising can drop information. Any AUC gain here is a conditional result: "the information dropped happened to be the noise."
- The verdict is FAIL (a flaw in the experiment design). R(0) = 1.0 and v01's fall to R(8) of 0.67 show a clear reaction to noise, but the AUC difference was 0.0. The cause is that the niah tasks run only 2–3 steps and reach finish before the summarising strategy (`summarize_after = 2`) ever fires — so v08 sends the same conversation as v01 and there is no comparison. Proposed fix: make the niah tasks multi-stage (requiring several mail searches and file reads) to increase the step count.
