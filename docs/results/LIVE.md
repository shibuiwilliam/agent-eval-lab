## 2. 未解決だった 2 つの疑問に答えが出た

| 疑問 | 実測結果 |
|---|---|
| Haiku 4.5 で `strict: true` のツール定義は使えるか | **使える**が、入れ子の object すべてに `additionalProperties: false` が要り、13 ツール同時では `400 Schema is too complex.`。さらに strict は v06 の植込み（誤った引数名からの復帰）を API 側で抑止して観測対象を消すため、**本プロジェクトでは使わない** |
| `effort` の形式と対応モデル | `output_config: {"effort": "low"}`。**Sonnet 5 は対応、Haiku 4.5 は 400**（`This model does not support the effort parameter.`）。ジャッジ（Sonnet 5）だけに付けた |

## 3. sim では観測できなかった 5 つの欠陥

| # | 欠陥 | sim | live（修正前） | 修正後 |
|---|---|---|---|---|
| L1 | エージェントが `finish` を呼ばず文章で終える | 0% | **80%** | 10% |
| L2 | 連絡先を引くツールが無く、宛先が分からず停止する | 起きない（意図に宛先が書いてある） | 発生 | `contacts_search` を追加して解消 |
| L3 | prompt が acceptance より情報が少ない（曜日が無い） | 起きない（意図に日付がある） | 発生（質問して停止） | prompt に曜日を明記して解消 |
| L4 | 受入基準が数値表記の揺れで偽陰性（`1,500円` vs `1500`） | 起きない | 発生（2/10 run） | `normalize_text` で解消 |
| L5 | sim が植込み版 v07 の効果を**逆向き**に誤っていた | v07 = 0.30 | **v07 = 0.97** | sim を修正し 0.79 |

### 修正前後の live 計測（10 タスク × v01_baseline、同一条件）

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 合格率 | 0.50 | **0.70** |
| `finish` 呼び出し率 | 0.20 | **0.90** |
| `claims` が空でない run | 0.20 | **0.90** |
| リンター違反の検出 | 0 件（偽陰性） | 1 件（`declare_completion_with_finish`） |

L1 は評価手法そのものを壊していた。`claim_done_requires_checks` は `finish` イベント起点だったため、
`finish` を呼ばない run では「書き込んだのに検査していない」を**一度も検出できなかった**。
規則を run 全体で判定する形に変え、`declare_completion_with_finish` を追加した。

## 4. sim の妥当性（実験 [E0-1](E0-1.md)）

同じ (task, version, repeat) 90 組を live と sim で突き合わせた結果。

| 指標 | 基準 | sim 修正前 | sim 修正後 | 判定 |
|---|---|---|---|---|
| 合否一致率 | ≥ 0.7 | 0.656 | **0.822** | ○ |
| 版ごとの合格率の最大差 | ≤ 0.15 | 0.667 | 0.167 | × |
| ツール名列の類似度 | ≥ 0.6 | 0.548 | **0.659** | ○ |
| 版の順序が保たれる | == 1 | 0 | 0 | × |

**sim が live と一致する量**: 合否（0.82）、ステップ数（live 3.04 / sim 3.28）、
検証行動率（live 0.29 / sim 0.33）、重複呼び出し率（live 0.006 / sim 0.0）。

**sim が live と一致しない量**:
- `stop_appropriate`: sim 1.0 / live 0.66。sim は必ず `finish` を呼ぶ。
  **`finish` に依存する指標（claims、自己申告忠実度、停止適切性）を sim の数値で語ってはいけない**。
- 版の順序: live では 3 版の合格率が 0.90 / 0.87 / 0.97 と、各版 n=30 の信頼区間（±0.11）に収まる幅しかない。
  順序そのものが統計的に定まらないので、この基準の書き方に問題がある。

## 5. live 検証が既存の結果に与えた影響

| 実験 | 変化 | 理由 |
|---|---|---|
| E4-4 半順序マイルストーン | PASS → **FAIL** | sim 修正で v01 / v03 / v07 の合格率が同点に近くなり、4 版では順位相関が定まらない（ρ = −0.27、p = 0.73）。全 12 版で取ると ρ = 0.63（p = 0.028）で関係自体は成立している |
| E4-9 Goodhart ペア | PASS 維持 | v07 のステップ比 0.795（基準 0.8）、検証行動率 0。live でも v07 は検査だけを省いており、主張と整合 |
| E8-5 ドリフト帰属 | PASS 維持 | 要因入替の設計修正が効いている |
| E3-3 / E3-7 選択 | FAIL 維持 | 原因（冗長性ペナルティの類似度）は sim 修正と独立 |
