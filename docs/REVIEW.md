## 1. 評価器の欠陥（A 系）

### A1【重大】反転の閾値が次元の違う量を比べていた → ADR-016

`_common.flake_band()` は v01 の**周辺合格率**の Wald 95% 半幅を返し、`flipped_tasks()` は
それを**対応のある不一致率**の閾値に使っていた。片方は「合格率がどれだけぶれるか」、
もう片方は「同じ (task, repeat) の対で合否が変わる確率」で、次元が違う。

しかも sim は `(task_id, seed, repeat)` に対して決定的で版をまたいで同じ運を使うので、
「版に効果が無い」という帰無仮説の下での不一致は**厳密に 0** である。閾値を置く根拠が無い。

| 変更 | 改訂前（帯あり） | 改訂後（帯なし） | 取り逃していた反転 |
|---|---|---|---|
| v09_model_swap | 4 | **23** | 19 件（83%） |
| v06_toolschema_v2 | 6 | **11** | 5 件（45%） |
| v02_dateformat | 10 | 10 | 0 |
| v05_unsafe_delete | 2 | 2 | 0 |

合格率 0.5 付近のタスクに 0.31 という大きな閾値が掛かるため、**最も情報量のある境界タスクで
最も信号を消していた**。影響は E3-1 / E3-3 / E3-4 / E3-7 / E8-5 の 5 実験。

修正後、E3-1 の `recall_of_flipped = 1.0` は 6 件ではなく **11 件すべて**を含むことを要求する。
判定は PASS のままなので、**この実験の結果は改訂前より強い主張になった**。

### A2【重大】逃走欠陥率が原典と違い、しかも予測と比較不能だった → ADR-018

原典 3.8 は `Escape(S) = |F_full \ S| / |F_full|`、`F_full` =「定期フル実行で見つかった**失敗**」。
実装は `F_full` を「**反転した**テスト」にしていた。

一方 `selector.expected_escape` は失敗質量 `Σ(1 − p̂_t)` で計算しており、**原典どおり失敗を予測**している。
つまり E3-3 の `calibration_error` は「失敗の予測」と「反転の実測」を引き算していた。
**比較不能な 2 量なので、この指標はどう転んでも意味を持たなかった。**

両者を失敗ベースでそろえると、校正誤差は **0.325 → 0.080**（基準 0.15）で成立する。
選択器は「自分がどれだけ失敗を見逃すか」を正しく見積もれていた。

### A3【重大】迂回率が原典の定義と違った → ADR-017

原典 4.2 は `D = L_actual / L_min`（1 以上の比）。実装は `(steps − l_min) / steps`（0〜1 の割合）で、
別の量だった。さらに `l_min` が未指定のとき 0 として扱うので `D` が常に 1.0 になっていた。
`detour_ratio`（原典どおり）と `detour_excess`（改訂前）に分けた。合格基準には入っていない。

### A4【重大】停止適切性が原典の定義と違った → ADR-019

原典 4.2 は「未達で完了宣言した率、達成後も継続した率」。実装は
**「最後のツール呼び出しが `finish` か」だけ**を見ており、達成/未達を参照していなかった。

これは E0-1 の結論を歪めていた。改訂前は sim 1.0 / live 0.66 で「sim と live が一致しない量」
の筆頭として結果ページに書かれていた。原典の定義に直すと:

| 指標 | live | sim | 一致するか |
|---|---|---|---|
| `stop_appropriate`（原典の定義） | 0.496 | 0.500 | **一致する** |
| `premature_stop`（未達で完了宣言） | 0.471 | 0.450 | **一致する** |
| `finish_called`（改訂前の量） | 0.683 | 1.000 | 一致しない |

**「sim は停止の適切さを再現できない」は誤りだった。**再現できていなかったのは
**ツール呼び出しの作法**であって、停止の適切さではない。両者を別の指標に分けた。

### A5【中】飽和判定が規則と違った

`.claude/rules/drift.md` は「**全版で**合格率 > 0.95 かつ |d| < 0.1」。実装は全 run を
**プールした**合格率を見ており、一部の版だけ低くても飽和と判定しえた。規則に合わせた。

## 2. 実験設計の欠陥（B 系）

### B1【重大】対照が対照になっていなかった → ADR-020

`selector.select()` は不可侵集合 3 件（T-005 / T-011 / T-025）を必ず含め、その予算を消費する。
対照の `select_random()` / `select_recent_failures()` は含めていなかった。
**同じ予算で比較しているつもりが、片方だけ 3 件を強制されていた。**対照にも同じ規則を適用した。

### B2【重大】分岐再実行が分岐ステップを二重に課金していた → ADR-021

`BranchRunner.run()` は分岐したステップの判断確認を `confirmations` に数えたうえで、
その直後に `resume_from=divergence` で**同じステップをもう一度**モデルに投げていた。
実装としては分岐確認で得た応答をそのまま再開に使えるので、1 分岐につき 1 ステップぶん過大だった。

E3-5 の `live_step_ratio_v02` は **1.113 → 1.000**。判定は NEGATIVE のまま（基準 0.6）で、
「接頭辞を辿り直すには 1 ステップにつき 1 回の課金確認が要る」という構造的な結論は変わらない。

### B3【中】不確実性の推定が変更に反応しない履歴を使っていた → ADR-022

E3-3 / E3-7 は `history = [r for r in runs if r.version_id != target]` として**11 版ぶん**を
プールして `p̂_t` を推定していた。原典 3.4 の「直近の合格率」は現行配備の履歴を指す。
11 版をプールすると `p̂` がイベントによらずほぼ同じ値になり、**選択が変更 Δ に反応しなくなる**。
履歴を v01_baseline に限った。

### B4【重大】SPRT の比較相手の式が二標本用だった → ADR-023

`fixed_n_for_power()` は第 1 種の誤りの項にプール分散 `((p0+p1)/2)` を使っていた。
これは**二標本**の比率差検定の公式である。ここで検定しているのは `H0: p = p0` 対 `H1: p = p1` の
**一標本・単純仮説**なので、帰無仮説下の分散は `p0(1−p0)` でなければならない
（実装は二標本の α 項と一標本の β 項を混ぜた、どちらでもない式だった）。

p0=0.5, p1=0.9, α=0.05, β=0.10 で **固定 n = 9（誤）／ 10（正）**。
比は **0.604 → 0.5436** となり、基準 0.6 を満たす。

合格基準は 1 文字も変えていない。変えたのは**測定器**の側であり、その根拠
（一標本検定の分散は帰無仮説下のもの）は判定を見なくても成り立つ。

### B5 基準が達成不能かどうかを確かめていなかった

E3-7 の「予算 40% で逃走欠陥率 ≤ 0.1」が達成可能かを誰も確かめていなかった。
各反復の `F_full` を事前に知っているオラクルを実装して下限を出した。

| 予算比 | オラクル（到達可能な下限） |
|---|---|
| 5% | 0.966 |
| 20% | 0.418 |
| 30% | 0.155 |
| 40% | **0.031** |
| 100% | 0.000 |

予算 40% の下限は 0.031 なので、**基準 0.1 は達成可能**である。届かないのは選択の側だと確定した。
E8-7 の lift ≥ 3.0 は逆に**達成不能**（一様でも 45% が重要セッションなので上限 2.2）であり、
これは実験設計の誤りとして FAIL のまま残す。

  CLAUDE.md「レポートから逸脱するときは ADR を書く」に違反していた。ADR-016〜023 を追加した。

## 4. 再実行で分かったこと

### 4.1 不確実性駆動の選択は、この環境ではランダムに勝てない（E3-3、NEGATIVE）

修正後に方策を 5 通り並べ、2 つの KPI（失敗ベース／反転ベース）で比較した。
数値はランダム選択に対する比で、**1 未満ならランダムより良い**。

| 方策 | 失敗 KPI 比 | 反転 KPI 比 |
|---|---|---|
| 原典どおり（カバレッジ優先 ＋ 冗長性） | 1.056 | 1.137 |
| 冗長性ペナルティを外す | 0.948 | 0.622 |
| `H(p̂)/c` だけ | 1.010 | 0.973 |
| 失敗確率 `(1−p̂)/c` | 0.760 | 0.797 |
| **カバレッジ重なりだけ** | 0.839 | **0.344** |

読み取れること:

1. **この環境で信号を持っているのは原典 3.2（カバレッジ）であって、3.4 の不確実性ではない。**
   カバレッジ重なりだけで選ぶと反転 KPI がランダムの 0.344 倍と最も良い。
   `H(p̂)/c` だけにすると 0.973 で、ほぼランダムと変わらない。
2. **冗長性ペナルティは信号を消している。**外すと 1.137 → 0.622 に改善する。
   ADR-014 のとおり、原因は類似度の定義ではなく sim の軌跡の単調さである。
3. それでも原典どおりのパイプライン全体では基準 0.5 に届かない。
   改訂前は FAIL（こちらの実装の不備）と診断していたが、**冗長性を外しても `H(p̂)` 単体では
   ランダムに勝てない**ので、原因を手法側に訂正して NEGATIVE とした。

理論的にも整合する。Escape は失敗確率の高いテストを選ぶと最小化されるが、`H(p̂)` は
`p̂ = 0.5` で最大になり、**ほぼ確実に落ちるテスト（`p̂ → 0`）を優先しない**。
情報利得の最大化（3.4 の目的関数）と逃走欠陥率の最小化（3.8 の KPI）は、そもそも別の最適化問題である。
**原典は両者を同じ節の中で「選択器の KPI」として並べているが、片方を最適化しても
もう片方は最適化されない。**

### 4.2 校正は成立していた（E3-3）

`expected_escape` と実測を同じ量でそろえると誤差 0.080（基準 0.15）。
**選択器は「自分がどれだけ失敗を見逃すか」を正しく見積もれている。**
改訂前の 0.325 は比較不能な 2 量を引き算していたことによる見かけの誤差だった。

### 4.3 SPRT の主張は成立していた（E3-6、PASS）

α = 0.0455（≤ 0.07）、β = 0.0516（≤ 0.12）、平均試行数は固定 n の 0.544 倍（≤ 0.6）。
ただし最も決着が遅い `p_true = 0.5` を格子に含めた上での値である。
「SPRT は固定 n の 60% 以下」と主張するときは、仮説の設定（p0, p1）と評価する
`p_true` の範囲を必ず添える必要がある。

### 4.4 分岐再実行の節約は成立しない（E3-5、NEGATIVE のまま）

二重課金を直しても live ステップ比は 1.000 で、基準 0.6 に遠い。
原典 3.6 は「実行コストは軌跡長 L から接尾辞長 L − i* に落ちる」と書いているが、
**接頭辞を辿り直すには 1 ステップにつき 1 回の判断確認が要り、版が変われば必ず課金される。**
原典のコストモデルはこの確認コストを勘定に入れていない。
トークン比は 1.024 でステップ比より低く、接頭辞キャッシュの効果はトークン側にだけ現れた。
