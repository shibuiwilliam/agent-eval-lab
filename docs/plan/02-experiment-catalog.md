# 実験カタログ

各実験は5項目（仮説・植込み条件・対照・合格基準・来歴）を持つ。`experiments/registry.yaml` はこのカタログから機械可読な形に写す。
「フレーク帯」= ベースライン v01 を 3 回走らせた合否のばらつき幅。この帯の内側の変化は変化と数えない。

---

## 3章 Predictive Test Selection

### E3-1 軌跡カバレッジ依存グラフ（3.2）
- 仮説: ツール変更で実際に反転したテストは全て候補集合 `T_cand(Δ)` に含まれ、候補は全件より十分小さい
- 植込み: v06_toolschema_v2（`calendar_search` の引数変更）。反転はコーパスの v01 → v06 で測る
- 対照: 合成変更 `Change(kind=tool, components={mail_send})`。`mail_send` を一度も呼ばないテストは候補に入らない
- 合格基準: recall_of_flipped = 1.0（フレーク除外後）、candidate_ratio ≤ 0.6、対照の候補に非該当テストが 0
- 来歴: replay

### E3-2 意味的影響推定（3.3）
- 仮説: プロンプト差分から LLM が列挙した影響タグで、日付関連タスクが選ばれ、反転テストを高再現率で捉える
- 植込み: v02_dateformat（日付書式の指示変更）
- 対照: 文体だけを変えた差分 `v02b_tone`（版として run は不要。diff だけ使う）。影響タグは全体の 20% 以下しか選ばない
- 合格基準: recall_of_flipped ≥ 0.8、対照の selected_ratio ≤ 0.2、カバレッジ単独より precision が高い
- 来歴: live（Haiku、10 呼び出し程度）＋ replay

### E3-3 不確実性駆動の選択（3.4）
- 仮説: 予算 30% で、`H(p̂)/c` に基づく選択はランダム選択と「直近失敗優先」より逃走欠陥率が低く、`expected_escape` は実測と校正されている
- 植込み: v02〜v09 の各変更を leave-one-change-out で評価
- 対照: 同予算のランダム選択（1,000 回抽選の平均）、直近失敗優先
- 合格基準: escape(uncertainty) ≤ 0.5 × escape(random)、|expected_escape − actual| ≤ 0.15
- 来歴: replay ＋ simulated

### E3-4 テストピラミッドの段判定（3.5）
- 仮説: 変更分類から決めた段は、反転が観測される最小の段以上である。LLM に見えない変更は L1 で止まり反転が無い
- 植込み: v02（prompt → L2 以上）、v06（tool → L3 以上）、v09（model → L4）
- 対照: `Change(kind=code)`（ツールラッパーのリファクタ。版ハッシュ不変）。L0〜L1 で停止し、非フレーク反転が 0
- 合格基準: decided_level ≥ observed_min_level が全植込みで成立、対照の非フレーク反転 = 0
- 来歴: replay

### E3-5 接頭辞キャッシュと分岐再実行（3.6）
- 仮説: 分岐再実行は通常実行と結果が一致し、小さな変更では live ステップを大きく減らす。大きな変更ほど早く分岐する
- 植込み: v02（小変更）と v09（モデル入替）を v01 の軌跡から分岐再実行
- 対照: v01 → v01 の自己分岐。replay が当たるので分岐せず live ステップ 0
- 合格基準: outcome 一致率 ≥ 0.8（20 タスク）、live_step_ratio(v02) ≤ 0.6、median divergence(v09) < median divergence(v02)、自己分岐の live ステップ = 0
- 来歴: live

### E3-6 SPRT 早期打切り（3.7）
- 仮説: SPRT は名目 α=0.05, β=0.10 に近い誤り率で、固定 n 法より少ない試行で決着する
- 植込み: `p_true ∈ {0.1, 0.3, 0.5, 0.7, 0.9}` の Monte Carlo（各 10,000 試行）。live は境界テスト 5 件
- 対照: 同じ検出力の固定 n 法
- 合格基準: 経験的 α ≤ 0.07、β ≤ 0.12、平均試行数 ≤ 固定 n の 60%、live 境界テストの平均決着 ≤ 8 run
- 来歴: simulated ＋ live（少量）

### E3-7 逃走欠陥率・ε-探索・不可侵集合（3.8）
- 仮説: 予算 40% で逃走欠陥率 ≤ 0.1。ε=0.05 でランダムテストが毎回混ざる。不可侵集合は予算に関係なく常に選ばれる
- 植込み: 全変更に対するフル実行結果と選択結果の比較
- 対照: 予算 100% → 逃走欠陥率 0
- 合格基準: escape ≤ 0.1、ランダム混入 ≥ 1 件／回、inviolable 選択率 = 100%（予算 5% でも）
- 来歴: replay

### E3-8 学習済み故障予測によるテスト選択（3.4 の `p̂_t` を教師ありで推定する）
- 仮説: 「変更 × テスト」の特徴量から**この変更でこのテストが回帰する確率**を学習すると、
  同じ予算でランダム選択より高い再現率で回帰を捕まえる。原典 3.4 の特徴量表は有効である
- 植込み: 原典 3.8 の「コールドスタート」に従って作る合成変更 37 件
  （プロンプト section の増減 13 / 設定 7 / ツール schema 1 / モデル入替 1 / ツール障害 12 / 2 要因同時 3）。
  各変更 × 46 タスク × 5 反復を sim で実行し、`data/pts_corpus/` に置く（既存コーパスとは分ける）
- 対照: (a) ランダム選択、(b) ベースライン故障率のみ（変更を見ない）、
  (c) カバレッジ重なりのみ、(d) 不確実性 `H(p̂)`（E3-3 で検証した方策）。
  いずれも同じ予算・同じ不可侵集合の制約で走らせる
- 合格基準:
  - `roc_auc` ≥ 0.75（**変更の族単位 leave-one-group-out** で hold-out した変更に対して）
  - `recall_at_budget_30` ≥ 0.80（予算 30% で回帰の 80% 以上を捕まえる）
  - `recall_ratio_vs_random` ≥ 2.0
  - `escape_ratio_vs_random` ≤ 0.5（原典 3.8 の KPI を回帰に対して測る。E3-3 と同じ基準値）
  - `control_random_recall` ≤ 0.6（対照が高すぎない＝課題が自明でないことの確認）
- 来歴: simulated

### E3-9 不確実性の役割は「探索」である（3.4 と 3.8 の切り分け）
- 仮説: `H(p̂)` による選択は「その回の逃走欠陥を減らす」ためではなく
  「**選択器の校正を保つ**」ために効く（原典 3.8 の ε-探索と同じ役割）。
  部分観測（選んだテストの結果しか見えない）で変更を逐次処理すると、
  探索を混ぜたほうが後半ラウンドの校正と逃走欠陥率が良くなる
- 植込み: 合成変更 37 件を族が偏らない順に並べ、ラウンドごとに
  「選んだテストの結果だけ」でモデルを更新する。探索比 ε ∈ {0.0, 0.05, 0.2} を比較。
  探索枠の中身は「不確実性 `H(p̂)` 上位」と「ランダム」の 2 通り
- 対照: ε = 0（純粋な活用）。全件観測（完全情報）を性能の上限として併記
- 合格基準:
  - `calibration_gain` > 0（ε = 0.05 の後半ラウンドの Brier が ε = 0 より小さい）
  - `escape_gain` ≥ 0（ε = 0.05 の後半ラウンドの逃走欠陥率が ε = 0 以下）
  - `exploration_cost` ≤ 0.10（探索に払う当該ラウンドの再現率の低下が 10 ポイント以内）
- 来歴: simulated

### E3-10 変更履歴に沿った逐次評価（prequential）とラーニングカーブ
- 仮説: **変更履歴とテスト履歴を台帳として記録し**、ラグ（前回このテストが走ってから／落ちてから、
  この要素が前回変更されてから）と変更量（変更行数・要素数）を特徴量に入れると、
  変更を時系列順に処理する現実的な運用（過去の記録だけで学習して次の変更を予測する）で
  (a) 履歴が積み上がるにつれ予測が良くなり、(b) 依存グラフ単独を上回る
- 植込み: 合成変更 65 件を変更履歴の順（`seq`）に並べる。同じ要素が 2〜7 回変更されるように
  作ってあり（section ごとに drop / truncate / emphasize、`max_steps` は 4 値、
  ツール障害は常時／2 ステップ目以降の 2 通り）、ラグに値が入る。
  変更 t を予測するときに使えるのは **`seq < t` の記録だけ**（未来は構造的に見えない）
- 対照: (a) カバレッジ重なりのみ、(b) **履歴特徴を外した同じモデル**（アブレーション）、
  (c) ランダム選択。いずれも同じ予算・同じ不可侵集合
- 合格基準:
  - `prequential_auc` ≥ 0.75（過去だけで学習して次の変更を予測したときの AUC）
  - `history_feature_gain` > 0（履歴・ラグ特徴を入れた AUC − 外した AUC）
  - `late_auc_gt_early_auc` == 1（後半の変更の AUC が前半より高い＝学習が積み上がる）
  - `recall_at_budget_30` ≥ 0.60（時系列プロトコルでの回帰の再現率）
  - `beats_coverage_baseline` == 1（prequential AUC がカバレッジ単独を上回る）
- 来歴: simulated

## 4章 過程・計画の評価

### E4-1 軌跡メトリクス（4.2）
- 仮説: 植込み版は対応する指標だけを動かす
- 植込み: v04_loopy（重複呼び出し率・後戻り↑）、v03_noverify（検証行動率↓）
- 対照: v01 の 3 反復（指標の分散が小さい）、v02（これらの指標は動かない）
- 合格基準: dup_rate(v04) ≥ 2 × v01、verification_rate(v03) ≤ 0.5 × v01、v02 の変化はフレーク帯内
- 来歴: replay

### E4-2 アブレーションによる無駄呼び出し判定（4.3）
- 仮説: v04 の無駄呼び出し率 `U` は v01 より高い。ジャッジ代理指標はアブレーションと十分一致する
- 植込み: v04 の 5 run と v01 の 5 run（全呼び出しをアブレーション）
- 対照: 直後の行動に結果が使われる呼び出し（search → create）は「有用」と判定される
- 合格基準: U(v04) − U(v01) ≥ 0.15、代理指標の precision / recall ≥ 0.7、対照の有用判定 ≥ 0.9
- 来歴: live

### E4-3 軌跡リンター（4.4）
- 仮説: 順序・禁止制約の違反を決定的に検出し、ベースラインでは誤検出しない
- 植込み: v05_unsafe_delete（`no_delete_without_backup`）、v03_noverify（`claim_done_requires_checks`）
- 対照: v01。手書きイベント列と hypothesis の性質テスト
- 合格基準: 植込み版の違反検出率 ≥ 0.8（該当行動を含む run のうち）、v01 の違反率 ≤ 0.1、演算子の単体テスト全通過
- 来歴: replay ＋ unit

### E4-4 半順序マイルストーン（4.5）
- 仮説: 部分点は版の品質順序と整合し、順序の異なる正当な経路に満点を与える
- 植込み: v01 / v03 / v05 のコーパス、および順序違いの合成軌跡（実装先行／テスト先行）
- 対照: 到達順序が制約に反する合成軌跡は減点される
- 合格基準: 版ごとの milestone_score と acceptance 合格率の Spearman ρ ≥ 0.6、合成軌跡の判定が期待どおり
- 来歴: replay ＋ unit

### E4-5 ステップ単位判定（4.6）
- 仮説: 行動を変異させたステップは、ルーブリック判定でも参照方策一致でも元より低く評価される
- 植込み: v01 の正常 run から 30 ステップを抽出し、誤ツール／誤引数／破壊的操作に置換
- 対照: 変異なしステップを 2 回判定して安定性を見る
- 合格基準: 変異ステップの低下率 ≥ 0.8（両方式）、元ステップの平均 ≥ 3.5/5、再判定の一致（±1）≥ 0.8
- 来歴: live（Sonnet、約 200 呼び出し）

### E4-6 計画の外在化と乖離率（4.7）
- 仮説: 計画を構造化出力させると DAG 検査が機能し、計画を無視する版は乖離率が高い
- 植込み: v12_ignore_plan（計画を出した後に無視する指示）
- 対照: v01p（v01 に `plan_first: true`）
- 合格基準: v01p の有効 DAG 率 ≥ 0.9、δ(v12) ≥ δ(v01p) + 0.2、乖離正当性ジャッジが植込みの不当な逸脱を ≥ 0.7 で不当と判定
- 来歴: replay ＋ live（少量）

### E4-7 軌跡内 NIAH（4.9）
- 仮説: 想起率 R(n) はノイズ n とともに下がり、要約戦略（v08）は raw（v01）より AUC が高い
- 植込み: niah タスク 4 種 × n ∈ {0, 2, 4, 8} × 3 反復
- 対照: n = 0 では両版とも高い想起率
- 合格基準: R(0) ≥ 0.8（両版）、R(8) ≤ R(0) − 0.2（v01）、AUC(v08) ≥ AUC(v01) + 0.1（成り立たなければ NEGATIVE として記録。要約が情報を落とす可能性は原典 4.11 が指摘している）
- 来歴: live

### E4-8 pass@k / pass^k と一貫性（4.10）
- 仮説: 境界タスクでは pass@k と pass^k の差が大きく、信頼性指標として pass^k が必要になる。ループ版はステップ数分散が大きい
- 植込み: v01 の 5 反復 × 10 タスク、v04 の 3 反復
- 対照: 自明タスクでは pass@3 ≈ pass^3
- 合格基準: 境界タスクで pass@3 − pass^3 ≥ 0.2、自明タスクで差 ≤ 0.05、Var(steps, v04) > Var(steps, v01)
- 来歴: replay

### E4-9 コスト予算と Goodhart ペア（4.11）
- 仮説: ステップ数最小化版は効率指標を改善するが、対になる検証行動率を落とす。p95 予算はループ版だけを弾く
- 植込み: v07_step_minimizer、v04_loopy
- 対照: v01
- 合格基準: steps(v07) ≤ 0.8 × v01 かつ verification_rate(v07) ≤ 0.7 × v01、p95 超過が v04 で検出され v01 で検出されない
- 来歴: replay

## 8章 テストの陳腐化対策

### E8-1 模擬忠実度と TTL（8.5）
- 仮説: 外部サービスが変わると `F` が下がり、不一致キーが特定される。期限切れカセットは警告される
- 植込み: `DriftInjector.bump_external(v2)`（`price` → `unit_price`、値の変化）
- 対照: 変更前は F = 1.0
- 合格基準: F(after) ≤ 0.5、不一致キー集合 == 変更したキー集合、TTL 超過の検出率 = 100%
- 来歴: replay（LLM 不要）

### E8-2 鮮度と分布距離（8.3）
- 仮説: 本番分布のシフトを JS ダイバージェンスが捉え、共適応の言い換えを MMD が捉える
- 植込み: `ProdStream` の日別シフト（新カテゴリ比率 0% → 40%）、Haiku による「慣れた言い方」への言い換え
- 対照: 同一分布からの再サンプル
- 合格基準: JS が日数に対して単調増加、新カテゴリ ≥ 25% で警報、MMD の p < 0.05（言い換え）かつ対照で p ≥ 0.05 が 90% 以上（ブートストラップ）
- 来歴: simulated ＋ live（言い換え生成 50 呼び出し程度）

### E8-3 弁別力と飽和（8.4）
- 仮説: 自明タスクは飽和と判定され、境界タスクは高い弁別力を持つ
- 植込み: 自明タスク T-901, T-902（全版で合格）
- 対照: 境界タスク（v01 合格率 0.3〜0.7）
- 合格基準: |d(T-9xx)| < 0.1 かつ飽和判定、境界タスクの d ≥ 0.3、飽和判定が `lifecycle` に届く
- 来歴: replay

### E8-4 二重トラック κ（8.6）
- 仮説: 模擬とライブの合否一致 κ はドリフト注入で下がる
- 植込み: `bump_external(v2)` 後に `external_lookup` を使う 20 タスクをライブで再実行
- 対照: 注入前の κ
- 合格基準: κ(before) ≥ 0.6、κ(before) − κ(after) ≥ 0.3
- 来歴: live

### E8-5 ドリフト帰属（8.8）
- 仮説: 要因別入替で主効果最大の要因が植込み原因と一致する
- 植込み: 単一要因変更 3 種（model: v09、prompt: v02、tool: v06）、2 要因同時変更 1 種
- 対照: 無変更（全主効果がフレーク帯内）
- 合格基準: 単一要因 3 種中 2 種以上で一致、2 要因では上位 2 が一致、無変更で警報なし
- 来歴: live（分岐再実行、8 組合せ × 10 タスク）

### E8-6 モデル指紋（8.8）
- 仮説: 固定プローブの分布比較は同一モデルの再取得では警報せず、モデル入替では警報する
- 植込み: Haiku → Sonnet の入替（無断更新の代替）
- 対照: Haiku の 2 回取得
- 合格基準: 対照の誤警報率 ≤ 0.1（ブートストラップ）、入替の検出 p < 0.05
- 来歴: live（約 150 呼び出し）

### E8-7 本番→テスト・パイプライン（8.2）
- 仮説: 層化サンプラーは重要セッションを優先し、ジャッジ起草の受入基準は人（または自動承認）に受け入れられ、登録後にスイートと本番の距離が縮む
- 植込み: `ProdStream` 3 日分のセッション（live）から 20 件を採取
- 対照: 一様サンプリング
- 合格基準: 失敗・高コスト・新カテゴリの採取率が一様の 3 倍以上、起草の承認率 ≥ 0.7、登録後の JS が登録前より小さい
- 来歴: live（synthetic prod）＋ Sonnet 30 呼び出し程度

### E8-8 ライフサイクル状態機械（8.10）
- 仮説: 遷移条件はメトリクスから決定的に動作し、Retired は終端である
- 植込み: 単体テストで各遷移を起こすメトリクスを与える
- 対照: 条件を満たさないメトリクスでは遷移しない
- 合格基準: 全遷移の単体テスト通過、Retired からの遷移が例外になる、`lifecycle.jsonl` が追記型
- 来歴: unit

### E8-9 汚染検知（8.9）
- 仮説: カナリア走査は汚染版を検出し、public/private の合格率差が汚染版で広がる
- 植込み: v10_contaminated（private タスクの canary 付き例文を few-shot に混入）
- 対照: v01
- 合格基準: 走査の検出率 = 100%（v10）、v01 で 0、gap(v10) ≥ 0.2 かつ gap(v01) ≤ 0.1
- 来歴: replay
