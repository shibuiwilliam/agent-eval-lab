# THETA — ROI の仮定パラメータの範囲 Θ（ADR-032 が参照する）

作成: 2026-11-07（W0-D3、designer）。改訂: 2026-11-07（W0 の突き合わせ）、2026-11-07（W0-Z: 損益分岐の nan の扱いを SPEC と実装に合わせた。Θ の値は変えていない）。状態: **案**。G0 でユーザーの承認を得て固定する（`docs/plan/coding/G0.md`）。
**値の正本は機械可読の `coding/theta.yaml`** であり、本書の 3 節の表はその写しと説明である（値を 2 か所で別々に直さない。食い違えば `theta.yaml` が正）。
**データ（パイロット・コーパス）を見る前に固定する**。固定後に変えるときは ADR を書き、変更前の Θ での結果も併記する。

## 1. 目的と使い方

`docs/NEW_IDEA.md` 原理 C と 4.0 節に従い、実験室で測れない人の費用を**仮定**として範囲で掃引し、版の優劣という**決定**がその範囲のどれだけで変わらないか（Rob）を報告する。
範囲は「もっともらしい中心」を当てるためではなく、**広さで仮定への依存を見せる**ために置く。個々の数値に出典は付けない（出典らしい数値を作らない）。根拠は、時給と所要時間の桁の見積りと、レビュー速度の一般的な目安だけである。

使う実験: EC-R1（Rob、損益分岐 $\pi_S^*$）、EC-R2（最適な k と再試行の閾値。記録のみ）。

## 2. 4.0 節の式との対応

$$
\mathbb{E}[C_{\text{del}}] = C_a + \pi_S\,R(\Delta_S) + \pi_F\,(R_F + H') + \pi_W\big(R(\Delta_W) + r H' + (1-r) D\big),\qquad
R(\Delta) = R_0 + \rho\,\lvert\Delta\rvert
$$

$$
\mathrm{NV} = H - \mathbb{E}[C_{\text{del}}],\qquad
\mathrm{Rob}(a \succ b) = \Pr_{\theta \sim \Theta}\big[\mathrm{NV}_a(\theta) > \mathrm{NV}_b(\theta)\big]
$$

| 記号 | 意味 | 測るか仮定か | 出どころ |
|---|---|---|---|
| $\pi_S, \pi_W, \pi_F$ | 3 類の確率 | 測る | live（隠しテスト） |
| $C_a$ | エージェントの 1 試行の費用 | 測る | live（台帳の実費、USD） |
| $\lvert\Delta_S\rvert, \lvert\Delta_W\rvert$ | 最終差分の行数（テスト以外のファイルの追加＋削除） | 測る | live |
| $H, H', R_0, \rho, R_F, D, r$ | 人の費用と検出率 | **仮定（Θ）** | 本書 |

NEW_IDEA 4.0 節の $R(\Delta)$ を、固定費 $R_0$ と 1 行あたりの費用 $\rho$ の 1 次式に具体化した（差分の大きさは live で測れるので、測れない部分だけを仮定にする）。

- **H は版の比較では打ち消す**（$\mathrm{NV}_a - \mathrm{NV}_b$ に H が入らない）。H が効くのは「任せるか自分でやるか」（NV > 0）と損益分岐の成功率 $\pi_S^*$ だけである
- 損益分岐: W と F の比 $q = \pi_W / (\pi_W + \pi_F)$ を版の実測で固定し、$c_S = R(\Delta_S)$、$c_W = R(\Delta_W) + rH' + (1-r)D$、$c_F = R_F + H'$ と置くと
  $\pi_S^* = \dfrac{q\,c_W + (1-q)\,c_F + C_a - H}{q\,c_W + (1-q)\,c_F - c_S}$
  - 改訂（W0-Z、2026-11-07）: SPEC.md 9.3 節と実装（`econ/roi.py` の `breakeven_success_rate`）どおり、**解が [0, 1] に無ければ nan** とする（旧版の「[0, 1] に切り詰め」はとらない。切り詰めると「どの成功率でも得」と「成功率 0 でちょうど損得なし」が同じ値 0 になり、分布が端に偽の質量を持つ）。$\pi_W + \pi_F = 0$（q が決まらない）か分母が 0 以下のときも nan
  - nan の θ は、その理由を区別して記録する（実験スクリプト W1-I8 の責務。損益分岐の分布は記録のみで基準に使わない）: q を固定した NV を $\pi_S = 0$ と $\pi_S = 1$ で評価し、両端とも $\mathrm{NV} \ge 0$ なら「常に得」、両端とも $\mathrm{NV} < 0$ なら「常に損」、それ以外（q が決まらない、分母が 0 以下で符号が変わる）は「定義なし」。結果ページには $\pi_S^*$ の分布と、3 つの別の割合を並べる

## 3. 範囲 Θ と分布

すべて独立に、**対数一様**で引く（桁の不確かさを等しく扱うため）。金額は USD、人の時間の単価はおおむね 50〜150 USD/時（中心 100）を念頭に置いた。

| パラメータ | 範囲 | 分布 | 中心（幾何平均） | 根拠 |
|---|---|---|---|---|
| H（人が自分でやる費用） | [20, 600] | 対数一様 | 110 | 200〜600 行の小リポジトリのバグ修正（特定・修正・テスト）に 15 分〜4 時間程度、時給 80〜150 の桁 |
| H'（差し戻し後の人のやり直し） | $H' = \kappa H$、$\kappa \in [0.5, 1.5]$ | κ を対数一様 | H × 0.87 | エージェントの試みが特定を助けて短くなる場合（0.5）から、誤った試みを読んだ分だけ長くなる場合（1.5）まで。H と独立に引くと「やり直しが自分でやるより桁違いに安い／高い」という不自然な組が混ざるので比で置く。含意される H' の範囲は [10, 900] |
| R_0（差分レビューの固定費） | [5, 50] | 対数一様 | 16 | 文脈の読み込み、CI の確認、説明文を読む 3〜30 分 |
| ρ（差分 1 行あたりのレビュー費用） | [0.1, 2.0] USD/行 | 対数一様 | 0.45 | 1 時間に読む行数の一般的な目安（数百行/時。速読で約 1,000 行/時、丁寧な読みで約 50 行/時）を時給 100 で換算。数値の出典は付けない |
| R_F（見える失敗の処理費用） | [2, 25] | 対数一様 | 7 | 赤いテストを見て試みを捨てる判断まで 1〜15 分 |
| D（漏れた欠陥の後始末） | [50, 10000] | 対数一様 | 707 | 数十分で直る軽微な不具合から、数日の障害対応まで。後工程ほど高いという通説は程度に異論が多いので、2.3 桁の幅で依存を見せる |
| r（W に対するレビュアーの検出率） | $1 - r \in [0.1, 0.8]$（r ∈ [0.2, 0.9]） | 見逃し率 $1-r$ を対数一様 | r ≈ 0.72 | W は可視テストに通り、もっともらしく見える誤りなので、見逃しは 1 割から 8 割まで。確率なので見逃し率の側で対数一様にした（見逃しが小さい側を細かく見る） |

- **標本数と seed**: N = 200,000、seed = 20261107（`coding/theta.yaml`。`numpy.random.default_rng(seed)`、軸を引く順は SPEC.md 9.3 節の `BaseParamName` の定義順（H, kappa, R0, rho, R_F, D, miss。`theta.yaml` の並びと同じ）に固定。seed は run manifest にも記録する）。Rob の標本誤差は $\sqrt{0.25/N} \approx 0.0011$ 以下で、基準の刻み（0.1）に比べて無視できる
- 標本は EC-R1・EC-R2 で共通に使い（同じ seed）、版の比較は同じ θ 標本の上で行う（共通乱数）
- 単価・時間の値を `pricing.yaml` には書かない（これはトークン単価ではなく仮定である）。実装（W1-I7 `econ/roi.py`）は `coding/theta.yaml` を `load_theta_space()` で読み、Θ を引数で受け取る（SPEC.md 9.3 節。旧版の未決は解決済み）

### 感度を見るための変種（記録のみ。基準には使わない）
| 変種 | 定義 |
|---|---|
| Θ_narrow | 各パラメータの範囲を、対数尺度で中心のまわり半分の幅に縮める |
| Θ_wide | 各パラメータの範囲を、対数尺度で中心のまわり 2 倍の幅に広げる（r は見逃し率で広げ、[0.01, 0.99] に切り詰める） |
| Θ_linear | 範囲は同じで、各軸を線形一様にする（ADR-032 影響: 対数一様が範囲の下側に質量を寄せる偏りの診断） |
| 1 変数ずつ | 1 つのパラメータを下側・中央・上側の 3 分位に制限したときの条件付き Rob（どの仮定が決定を左右するか） |

## 4. この Θ の性質（データを見る前に計算。simulated）

差分 10 行、$C_a$ の差を無視したときの値。N = 200,000。

| 量 | 値 | 意味 |
|---|---|---|
| $\Pr_\Theta[\,c_W > c_F\,]$ | 0.887 | W が F より高くつく θ の割合。**F→W の移動だけからなる版の差では、Rob の到達上限がこの値になる** |
| $\Pr_\Theta[\,c_W > c_S\,]$ | 1.000 | W は S より常に高くつく（S→W の移動は Θ 全体で劣化） |
| $\Pr_\Theta[\,c_F > c_S\,]$ | 0.927 | F が S より高くつく θ の割合 |
| $\Pr_\Theta[\,D > H'\,]$ | 0.846 | 4.0 節の帰結 1 の条件の一部 |

W の増分 0.15 の出どころと Rob(c01 ≻ c13) の到達上限（c01 = (0.60, 0.08, 0.32) と仮定）:

| S から来る割合 | 0 | 0.05 | 0.10 | 0.20 | 0.50 | 1.0 |
|---|---|---|---|---|---|---|
| Rob の到達上限 | 0.887 | 0.911 | 0.935 | 0.965 | 0.996 | 1.000 |

- EC-R1 の `rob_c01_over_c13 >= 0.9` は、c13 の W がすべて F から来る場合は到達不能である。これは Θ の性質であり、Θ を狭めて（たとえば D の下限を上げて）通すことはしない
- 真の差が 0 の対照で Rob が 0.5 付近に来るとは限らない（EC-R1 の方法を参照）。Rob は点推定の差の向きでほぼ決まり、0 か 1 に張り付きやすい。対照の基準は同時信頼帯を使う別の量で置く（EC-R1 の提案）
- 以上の値は W0-D3 の事前計算（作業用のスクリプト、seed 20261107）で得た。W1-I7 の実装で再計算し、値が一致することを単体テストの外の確認として W2 で記録する

## 5. 決めたこと・決めていないこと

- 決めたこと: 7 パラメータの範囲と分布、H' を H との比で置くこと、r を見逃し率で置くこと、N、共通乱数、感度の変種
- G0 で判断を受けること（`docs/plan/coding/G0.md`）: (1) 範囲そのもの（ユーザーの現場感覚で桁が外れていないか）、(2) 差分の行数に依存するレビュー費用を 1 次式にしてよいか（大きな差分ほど 1 行あたりの注意が落ちる効果は入れていない）、(3) Rob の到達上限 0.887 の読み方
- 決めたこと（G0 に載せない）: H' を H の比で置く（独立に引く変種は記録にも足さない。$\kappa$ の範囲がその不確かさを持つ）、承認者モデル（EC-S3）は第 1 段では使わないので本書に入れない（ADR-032 判断 6）
